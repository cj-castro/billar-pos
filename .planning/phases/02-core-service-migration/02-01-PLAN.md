<objective>
Make the Flask/eventlet backend runnable as a native Windows Service (NSSM-wrapped), independent of Docker (SVC-01), and eliminate the last `host.docker.internal` references so the backend reaches the print agent via `localhost` by default (NET-01).

Purpose: The backend is the central aggregate of this system (ticket lifecycle, billing, Socket.IO). It must run correctly on native Windows before any other service migration is meaningful, and its print-agent networking must work without Docker Desktop's special DNS name.

Output: `backend/service_entry.py` (native service entrypoint replicating `entrypoint.sh`'s idempotent startup sequence) and `scripts/install-nssm-backend.ps1` (NSSM registrar), plus updated `PRINT_AGENT_URL` defaults in two backend source files.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Browser (LAN) → nginx → Backend | Untrusted client input crosses into the Flask API; unchanged by this plan (existing JWT/role checks apply) |
| install-nssm-backend.ps1 → Windows Registry (NSSM config) | Secrets read from `.env` are written into the NSSM service's environment block, persisted in the registry |
| Backend process → Print Agent (localhost:9191) | Backend now always targets localhost by default; no cross-host trust boundary remains for this path |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Information Disclosure | scripts/install-nssm-backend.ps1 (NSSM AppEnvironmentExtra) | mitigate | Script reads secrets from the git-ignored repo-root `.env` file at install time via `Read-DotEnv`; no secret value is ever hardcoded into the committed `.ps1` file. Full encrypted-at-rest secret storage (Windows Credential Manager) is explicitly Phase 3 (SEC-01) — residual risk transferred there, not silently dropped. |
| T-02-02 | Elevation of Privilege | BilliardBarBackend service (ObjectName LocalSystem) | accept | Matches the already-production-accepted print-agent precedent (`scripts/install-nssm-print-agent.ps1`); LAN-only, single-machine, physically-secured bar deployment. Medium severity, not high, given no external network exposure of this host. |
| T-02-03 | Tampering | backend/service_entry.py subprocess calls (flask init-db, seed.py) | mitigate | Both subprocess calls use `check=True` with no shell interpolation of untrusted input (fixed argv lists, not shell strings) — no command-injection surface introduced. |
| T-02-04 | Denial of Service | PRINT_AGENT_URL default change | accept | Changing the fallback default cannot affect the Docker deployment (docker-compose.yml supplies its own explicit default), so no regression risk to the live bar machine. |

Severity note: No HIGH-severity unmitigated threat is introduced by this plan. T-02-01 (the only information-disclosure item) is actively mitigated (kept out of git) with the remaining hardening explicitly tracked in Phase 3, not ignored.
</threat_model>
