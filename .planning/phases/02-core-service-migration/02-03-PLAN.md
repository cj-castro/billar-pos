<objective>
Serve the built React SPA via a native Windows nginx binary, reverse-proxying `/api/` and `/socket.io/` to the native backend — without Docker (SVC-03).

Purpose: nginx is the single entry point staff's browsers hit; `frontend/nginx.conf` already implements exactly the routing needed (D-11) — this plan ports it to a native Windows nginx install with only the two path/hostname changes the native environment requires.

Output: `scripts/nginx-windows.conf` (adapted proxy config) and `scripts/install-nssm-nginx.ps1` (download, deploy, register as an NSSM service per D-12).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| LAN browser (staff device) → nginx:8080 | Untrusted network input from any device on the bar's LAN — same exposure as the current Docker setup's `FRONTEND_PORT` mapping |
| install-nssm-nginx.ps1 → nginx.org (internet download) | Supply-chain trust: the script fetches a third-party binary over HTTPS at install time |
| nginx → Backend (localhost:5000) | Internal-only; not exposed via the firewall rule opened by this plan |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-09 | Tampering | install-nssm-nginx.ps1 (nginx.org binary download) | mitigate | Version is pinned explicitly (1.26.2) rather than a "latest" redirect, and the URL is restricted to the official `nginx.org` domain over HTTPS — same pattern already accepted for NSSM downloads from `nssm.cc` in the production print-agent script. |
| T-02-10 | Information Disclosure | Plain HTTP (no TLS) on the LAN | accept | Explicit, locked user decision D-13 — matches current Docker behavior exactly; LAN-only, on-site deployment; HTTPS is explicitly out of scope for this migration phase. |
| T-02-11 | Denial of Service / Info Disclosure | Firewall rule opens port 8080 to the whole LAN | accept | This is the intended, required exposure (staff must reach the POS from floor devices) and exactly matches the current Docker deployment's `FRONTEND_PORT` mapping — no new exposure introduced. |
| T-02-12 | Elevation of Privilege | BilliardBarNginx service (ObjectName LocalSystem) | accept | Same accepted-risk rationale as T-02-02/T-02-06 — matches the print-agent precedent; nginx itself has no code-execution surface beyond serving static files and proxying, unlike the Python services. |

Severity note: No HIGH-severity unmitigated threat is introduced by this plan. The one supply-chain item (T-02-09) is mitigated via version pinning and an official-domain-only source.
</threat_model>
