Purpose: This is one of the phase's explicit ROADMAP success criteria ("scheduler and Telegram bot run as their own independent native Windows services, decoupled from backend crashes") — it must be provably true within Phase 2, not deferred to Phase 4's reliability hardening.

Output: `scripts/install-nssm-scheduler.ps1` and `scripts/install-nssm-telegram-bot.ps1`, each registering a separate NSSM service with its own virtualenv (D-07).
</objective>

backend/scheduler.py — already correct for Windows, no code changes needed. It builds its own Flask app via create_app() for DB access and blocks forever on scheduler.start() (BlockingScheduler). NSSM must point directly at this file (no wrapper needed — unlike the backend, there is no init-db/seed step here).

telegram-bot/bot.py — already correct for Windows, no code changes needed. Reads TOKEN, ADMIN_CHAT_ID, DATABASE_URL from os.environ at import time and raises ValueError if any are missing — so the NSSM AppEnvironmentExtra for this service MUST set all three or the service will exit immediately on every start attempt. Uses a raw SQLAlchemy engine (create_engine(DATABASE_URL)), not Flask-SQLAlchemy — independent of the backend/scheduler's Flask app entirely.

docker-compose.yml scheduler.environment block (lines 91-101): DATABASE_URL, SECRET_KEY, TZ, FLASK_APP, SMTP_HOST, SMTP_PORT, SMTP_USER, SMTP_PASSWORD, REPORT_FROM, REPORT_TO.
docker-compose.yml telegram-bot.environment block (lines 113-118): TELEGRAM_TOKEN, ADMIN_CHAT_ID, DATABASE_URL.
Both DATABASE_URL values are built the same way as the backend's: postgresql://${POSTGRES_USER}:${POSTGRES_PASSWORD}@postgres:5432/${POSTGRES_DB} in Docker → must become @localhost:5432 on native Windows (same Pitfall #5 fix as Plan 01).

NSSM registration pattern (scripts/install-nssm-print-agent.ps1 lines 36-141) — copy this exact shape for both scripts: NSSM locate/install, venv creation, nssm install <Service> <VenvPy> <Script>, AppDirectory, AppStdout/AppStderr + AppRotateFiles 1 + AppRotateBytes, Start SERVICE_AUTO_START, ObjectName LocalSystem, AppEnvironmentExtra, AppExit Default Restart + AppRestartDelay 5000.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| install-nssm-scheduler.ps1 / install-nssm-telegram-bot.ps1 → Windows Registry (NSSM config) | SMTP credentials and the Telegram bot token are read from `.env` and written into each service's NSSM environment block |
| Telegram Bot Service → Telegram Bot API (outbound HTTPS) | Bot polls api.telegram.org using TELEGRAM_TOKEN; outbound only, no inbound webhook exposure |
| Scheduler / Telegram Bot → Postgres (localhost:5432) | Both connect directly via SQLAlchemy, independent of the backend process — same DB credentials, same trust level as the backend |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-05 | Information Disclosure | scripts/install-nssm-scheduler.ps1, scripts/install-nssm-telegram-bot.ps1 (AppEnvironmentExtra: SMTP_PASSWORD, TELEGRAM_TOKEN) | mitigate | Both scripts source secrets from the git-ignored `.env` at install time via the shared Read-DotEnv pattern; never hardcoded into the committed `.ps1` files. Full encrypted secret storage is Phase 3 (SEC-01) — residual risk explicitly transferred, not dropped. |
| T-02-06 | Elevation of Privilege | BilliardBarScheduler, BilliardBarTelegramBot (ObjectName LocalSystem) | accept | Same accepted-risk rationale as T-02-02 in Plan 01 — matches the production-proven print-agent precedent; LAN-only, single-machine deployment. |
| T-02-07 | Denial of Service | BilliardBarTelegramBot crash-loop if TELEGRAM_TOKEN/ADMIN_CHAT_ID unset | mitigate | Install script explicitly warns (not silently fails) when either value is missing from `.env`; NSSM's AppExit Default Restart + AppRestartDelay 5000 prevents a tight crash loop from consuming CPU. |
| T-02-08 | Spoofing | Telegram Bot API responses | accept | python-telegram-bot's HTTPS client validates the api.telegram.org TLS certificate by default; no custom transport is introduced by this plan. |

Severity note: No HIGH-severity unmitigated threat is introduced by this plan. Both information-disclosure items (T-02-05) are mitigated by keeping secrets out of git, with full hardening explicitly tracked in Phase 3.
