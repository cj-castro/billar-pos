<objective>
Consolidate every Phase 2 service's logs (backend, scheduler, telegram-bot, print-agent, nginx wrapper, and nginx's own native HTTP logs) into one shared, rotated, ACL-restricted directory (`C:\POS\logs\`), and give the operator one script to tail all of them live (LOG-01, LOG-02, LOG-03).

Purpose: today an operator debugging a problem must know five different per-service log locations, or Event Viewer. This plan makes "check the logs" a single command and ensures no log can silently fill the 8GB machine's disk.

Output: `scripts/reconfigure-log-paths.ps1` (D-01/D-03), nginx native logging directives in both configs plus `scripts/rotate-nginx-logs.ps1` (D-02), and `scripts/tail-logs.ps1` (D-04/D-05).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| C:\POS\logs\ directory ACL | New shared directory readable by any process that can reach it — must not be world-readable |
| Log content itself | Application logs may incidentally capture request metadata, IPs, ticket IDs — not raw secrets, but still operational data |
| Scheduled Task (rotate-nginx-logs.ps1) | Runs unattended as SYSTEM on a schedule, invoking a repo-tracked script path |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Information Disclosure | C:\POS\logs\ readable by any local user (default inherited ACL) | mitigate (HIGH) | Task 1 explicitly restricts the directory ACL to Administrators + SYSTEM via `icacls /inheritance:r` immediately after directory creation, before any service writes to it. |
| T-03-02 | Tampering | `nssm set` applied to a running service silently no-ops (Pitfall 1) | mitigate | Task 1 always stops the service before `nssm set` and verifies via `nssm get` before restarting; script exits non-zero on mismatch rather than reporting false success. |
| T-03-03 | Denial of Service | nginx native access/error logs have no built-in rotation and could fill disk on the 8GB machine | mitigate | Task 2's rotate-nginx-logs.ps1 renames + prunes daily via a self-registering Scheduled Task; NSSM's existing AppRotateFiles/AppRotateBytes already covers the other 5 wrapper logs. |
| T-03-04 | Elevation of Privilege | rotate-nginx-logs.ps1's Scheduled Task runs as SYSTEM unattended | accept | Matches the existing precedent of every Phase 2 NSSM service already running as LocalSystem (T-02-02); the script only touches files under C:\POS\logs\ and restarts one already-SYSTEM-owned service. |
| T-03-05 | Information Disclosure | scripts/tail-logs.ps1 requires no elevation, so any local account could run it if it also has NTFS read access to C:\POS\logs\ | accept | Directory ACL (T-03-01's mitigation) is the actual gate — tail-logs.ps1 itself does nothing an attacker with existing read access couldn't already do via `Get-Content` directly. |

Severity note: One HIGH-severity item (T-03-01, world-readable log directory) is explicitly mitigated in Task 1 via icacls before any log content is ever written there.
</threat_model>
