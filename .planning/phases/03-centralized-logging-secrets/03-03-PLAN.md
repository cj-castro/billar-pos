<objective>
Move every in-scope secret (D-07) out of the plaintext `.env` file and into DPAPI-encrypted storage under `C:\POS\secrets\`, then actually rewire the three secret-consuming NSSM services to source those values from the encrypted store instead of `.env` (SEC-01).

Purpose: `.env` being git-ignored already keeps secrets out of the repo, but it still sits on disk in plaintext indefinitely. This plan proves both halves of D-06/D-09: secrets can be encrypted at rest AND the running services actually consume the encrypted copy, not just a parallel copy nobody uses.

Output: `scripts/migrate-secrets-to-dpapi.ps1` (D-06/D-07/D-09) and `scripts/reconfigure-secrets.ps1` (D-06/D-09, mirrors reconfigure-log-paths.ps1's stop/set/verify/restart pattern but for AppEnvironmentExtra).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| .env (plaintext, git-ignored, on-disk) | The pre-migration source of truth for every secret — this plan's entire purpose is reducing reliance on it |
| C:\POS\secrets\*.dat (DPAPI-encrypted, on-disk) | The post-migration source of truth — encrypted at rest, decryptable by any local Administrator (LocalMachine scope) |
| NSSM AppEnvironmentExtra (in-memory, per-process) | Accepted plaintext-in-memory limitation per D-06 — secrets end up here regardless of which script sourced them |
| PowerShell console/transcript output during migration/reconfiguration | Must never carry a plaintext secret value |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-09 | Information Disclosure | Plaintext secrets sitting indefinitely in `.env` on disk | mitigate (HIGH) | Task 1 encrypts every D-07-scoped secret present in `.env` via DPAPI (AES-based, LocalMachine-scoped) into `C:\POS\secrets\`; Task 2 rewires the 3 secret-consuming services to actually source from that encrypted copy, so `.env`'s plaintext values stop being the operative source. |
| T-03-10 | Information Disclosure | C:\POS\secrets\ readable by any local user (default inherited ACL) | mitigate (HIGH) | Task 1 restricts the directory ACL to Administrators + SYSTEM via `icacls /inheritance:r` immediately after directory creation, mirroring Plan 03-01's log-directory ACL. |
| T-03-11 | Information Disclosure | Migration/reconfiguration script accidentally echoes a decrypted secret to console, transcript, or Scheduled Task history | mitigate | Explicit acceptance criteria in both tasks forbid printing decrypted values; only key names, booleans, and non-secret markers (e.g. presence of `DATABASE_URL=`) are ever printed. |
| T-03-12 | Information Disclosure | DPAPI `LocalMachine` scope means ANY local administrator (not just the account that ran the migration) can decrypt the store | accept | Deliberate choice over `CurrentUser` scope specifically to avoid the cross-account decryption failure documented in 03-RESEARCH.md Pitfall 2; this is a narrower version of D-06's own already-accepted limitation (plaintext secrets are already readable by any local admin via `AppEnvironmentExtra`/Process Explorer once a service is running) — DPAPI's value here is protecting the at-rest copy, not restricting which admin can eventually reach the value. |
| T-03-13 | Tampering | `nssm set ... AppEnvironmentExtra` applied to a running service silently no-ops (same class of issue as Pitfall 1 in Plan 03-01) | mitigate | Task 2 always stops the service first and verifies via `nssm get` before restarting, matching Plan 03-01's Task 1 pattern. |

Severity note: Two HIGH-severity items (T-03-09 plaintext-at-rest, T-03-10 unrestricted directory ACL) are both explicitly mitigated in Task 1 before Task 2 ever reads from the store.
</threat_model>
