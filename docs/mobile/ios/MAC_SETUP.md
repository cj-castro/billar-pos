## 4. Install and build

Run from the repo root on the Mac:

```bash
cd mobile
npm ci                        # uses mobile/package-lock.json; do not use npm install (would rewrite the lock)
npx expo install --check      # reports SDK-bundled native module drift; do not auto-fix without review
npm run typecheck
npm test
```

Generate the native project and build for the simulator:

```bash
npx expo prebuild --platform ios          # creates ios/ (git-ignored), runs pod install
npx expo run:ios                           # builds, installs, launches on the default simulator
```

Pick a specific simulator:

```bash
xcrun simctl list devices available        # find a name and UDID
npx expo run:ios --device "iPhone 16"      # name from the list; use the exact name shown
```

Clean regenerate after native config changes:

```bash
npx expo prebuild --platform ios --clean   # wipes ios/ and regenerates; re-run pod install if needed
```

Build issues to expect:

| Symptom | Likely cause | Action |
|---|---|---|
| `pod install` fails | CocoaPods out of date or repo cache | `pod repo update` then re-run prebuild. Do not hand-edit the Podfile. |
| "No such module" for a native package | Stale pods | `npx expo prebuild --platform ios --clean` |
| Xcode signing error for simulator | Simulator builds do not need a team. Error suggests a device profile | Choose a simulator destination |
| Long build or DerivedData bloat | Normal for first build | `rm -rf ~/Library/Developer/Xcode/DerivedData` only if needed |

## 5. Physical iPhone (local, free Apple ID)

Scope: local install for testing only. No TestFlight, no App Store (project rule). A free Apple ID provisioning profile **expires after 7 days**; re-run the build to renew it.

1. Connect the iPhone by USB. On the iPhone, enable Developer Mode: Settings > Privacy & Security > Developer Mode (restart and confirm). Confirm the exact path on your iOS version.
2. In Xcode: Settings > Accounts > add the Apple ID. Note the "Personal Team" that appears.
3. Open `mobile/ios/<workspace>.xcworkspace` (generated) in Xcode. Select the app target > Signing & Capabilities:
   - Automatically manage signing: on
   - Team: your Personal Team
   - Bundle identifier: `com.bola8.staff`. If Xcode reports the identifier is taken or unavailable for your team, change it **on the Mac only** (for example `com.<yourname>.bola8staff`) and record the change. Do not commit it.
4. Run on the device from Xcode, or `npx expo run:ios --device "<iPhone name>"`.
5. On the iPhone, trust the developer profile: Settings > General > VPN & Device Management > trust the Apple ID.
6. Launch the app and allow **Local Network** when prompted (section 6.2). If you deny it, re-enable in Settings > Privacy & Security > Local Network.

Device checks before testing with the bar backend:
- The phone and POS host are on the same SSID (`BAR_MACHINE_REQUIREMENTS.md` N4).
- `http://<pos-ip>:8080/api/v1/health` opens in Safari on the phone. If Safari is blocked by ATS or the local-network prompt, the app will fail too.

## 6. Connectivity configuration (apply on the Mac, NOT applied in this worktree)

### 6.1 App Transport Security (plain HTTP to the LAN)

The LAN backend is `http://` (nginx :8080). iOS blocks cleartext HTTP by default. Android uses `usesCleartextTraffic` (set through `expo-build-properties` in `mobile/app.config.ts`). The iOS equivalent goes under `ios.infoPlist` in `mobile/app.config.ts`.

Proposed change (to apply on the Mac):

```ts
// mobile/app.config.ts, inside `ios: { ... }`
ios: {
  bundleIdentifier: 'com.bola8.staff',
  supportsTablet: false,
  infoPlist: {
    NSLocalNetworkUsageDescription:
      'Bola 8 Staff se conecta al servidor del bar en tu red local.',
    NSAppTransportSecurity: {
      // Apple: NSAllowsLocalNetworking covers unqualified names, .local names and IP literals.
      NSAllowsLocalNetworking: true,
      // Fallback if raw IP connections are still blocked on the target iOS version:
      // add one entry per POS IP (ATS exception domains cannot take a CIDR range):
      // NSExceptionDomains: {
      //   '192.168.1.22': { NSExceptionAllowsInsecureHTTPLoads: true, NSIncludesSubdomains: false },
      // },
      // Last resort, only if the above fails on the target iOS version. Dev-only; remove before any future store submission:
      // NSAllowsArbitraryLoads: true,
    },
  },
},
```

Sources and caveats:
- Apple's `NSAllowsLocalNetworking` reference says it controls unqualified domains, `.local` domains and IP addresses over IPv4 or IPv6 (developer.apple.com, `NSAllowsLocalNetworking` page).
- Developer-forum reports are mixed. Some say a plain-HTTP LAN IP works with no ATS section. Others report HTTPS to a private IP still failing with the local-networking key, and iOS 17+ tightening of IP literals. **Test on the real device and the target iOS version.** Record which key was needed in `IOS_READINESS.md`.
- The app code does not apply the HTTP policy on iOS yet. `TECH_STACK_DECISION.md` section 6 asks for a private-host URL guard. It is not implemented (`REAL_BACKEND_VALIDATION.md` D-5).

### 6.2 Local Network permission (iOS 14+)

- iOS shows a one-time prompt the first time the app connects to a LAN address. The text comes from `NSLocalNetworkUsageDescription` (above). Without the key the prompt does not appear and connections fail silently.
- If the user denies the prompt, the app cannot reach the POS. The app should show the "Sin conexion" state with a hint to enable Settings > Privacy & Security > Local Network. **Not implemented yet; add to the iOS checklist** (`IOS_READINESS.md`).
- Bonjour keys (`NSBonjourServices`) are not needed: the app uses a typed IP/host, not discovery.

### 6.3 Simulator networking

- The iOS simulator shares the Mac's network. The backend running on the Mac is reachable at `http://localhost:8090` (the Android emulator uses `10.0.2.2` instead).
- Start the local stack on the Mac. This is the bash equivalent of `scripts/mobile/start-local-backend.ps1`, **not run here**. The values are dev-only:

```bash
cd <repo root>
FRONTEND_PORT=8090 \
SECRET_KEY=mobile-dev-secret-key \
JWT_REFRESH_SECRET=mobile-dev-refresh-secret \
POSTGRES_PASSWORD=mobile_dev_pg \
docker compose -p billarmobile up -d --build postgres backend frontend
curl -s http://localhost:8090/api/v1/health
```

- Use `http://localhost:8090` in the app's setup screen. The setup normaliser keeps the explicit port (it does not add one, see `REAL_BACKEND_VALIDATION.md` D-4).
- Seed credentials (dev stack only): the same table as `LOCAL_DEV_ENVIRONMENT.md` (admin, manager, waiter1, kitchen, barstaff).

### 6.4 Device to Mac backend

A physical iPhone can reach the Mac's stack at `http://<mac-lan-ip>:8090` if the Mac firewall allows it (System Settings > Network > Firewall, allow Docker or the port). This is a dev-only path. The bar path is `BAR_MACHINE_REQUIREMENTS.md`.
