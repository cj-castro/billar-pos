# iOS build and test guide (Bola 8 Staff app)

Builds the Expo app `com.bola8.staff` for the iOS Simulator on a Mac, with no EAS and no Apple account. Verified on the simulator only; see the known issues below. Test results: `docs/mobile/testing/ios/TEST_RESULTS_IOS.md`. Mac setup background: `docs/mobile/ios/MAC_SETUP.md`.

## Prerequisites

| Tool | Version used |
| --- | --- |
| macOS | 27.3 |
| Xcode | 26.6. After any OS or Xcode update run `xcodebuild -runFirstLaunch` |
| iOS Simulator runtime | iOS 26.5 (iPhone 17 Pro) |
| CocoaPods | 1.17 |
| Node / npm | Node 25, npm 11 |
| Watchman | any current Homebrew build (`brew install watchman`) |
| PostgreSQL | Homebrew `postgresql@17` (`/opt/homebrew/opt/postgresql@17`) |
| Python | Homebrew `python@3.12`. The backend pins (eventlet 0.36, greenlet 3.0, psycopg2-binary 2.9.9) do not build on 3.15 |
| E2E only | Maestro 2.12 and JDK 17 |

Disk: a simulator build needs about 13 GB free. Check with `df -h /` before building.

## 1. Start the local backend

```bash
scripts/mobile/start-local-backend.sh          # default port 8090
```

- Postgres DB `billiardbar_mobile`, role `billiard`. The script never touches a DB named `billiardbar`.
- Creates the venv under `.local-backend/venv`, runs `init-db`, `seed.py`, `factory-finalize` and `apply-migrations`, then serves on `0.0.0.0:8090`.
- Log: `.local-backend/backend.log`. Stop: `kill "$(cat .local-backend/backend.pid)"`.
- Health check: `curl -sf http://localhost:8090/api/v1/health`.

## 2. Build and launch the app

```bash
scripts/mobile/build-ios.sh "iPhone 17 Pro"    # or a UDID; --clean re-runs expo prebuild and pod install
```

The script boots the simulator, runs `npm ci` if needed, runs `expo prebuild --platform ios` if `mobile/ios/` is missing, runs `pod install`, then `expo run:ios` (Metro stays in the foreground; Ctrl-C stops it).

On the first screen (setup), enter **`localhost:8090`**. The simulator shares the Mac's network, so `localhost` reaches the backend. Use the Mac's LAN IP only for a physical device.

## 3. Tests

Run from `mobile/`.

**Jest** (unit and integration; uses the local backend for contract tests):

```bash
cd mobile && npx jest
```

Last run: 59 suites, 619/619 passed in 8.6 s with no retry. On a cold cache a few tests can hit the 5 s timeout; a warm retry passes.

**Maestro** (E2E, flows in `mobile/e2e/maestro`):

```bash
export MAESTRO_DRIVER_STARTUP_TIMEOUT=300000
cd mobile/e2e/maestro
maestro --device <SIMULATOR_UDID> test j1-waiter-order.yaml
```

Find the UDID with `xcrun simctl list devices available`.

Run the iOS flows in this order, because they share state: `j12-touch-targets-waiter`, `j1-waiter-order`, `j15-kds-undo`, `j12-pay-cash`, `j13-express-order`, `j14-waiting-assign`, `j17-admin-reports`, `j18-admin-more-system`, `j16-manager-cash`. Before `j16`, close any open tickets. Its cash steps need no open register or tickets.

The `_login` subflow dismisses the iOS "Save Password?" sheet when it appears. The j2 to j11 flows and the legacy `*-flow.yaml` files still use the Android server address `10.0.2.2` and were not converted for iOS.

### XCUITest runner starts suspended (SIGCONT workaround)

On this host the Maestro driver process `maestro-driver-iosUITests-Runner` can start in the stopped state (`T`). Maestro then fails with "iOS driver not ready in time", even with long timeouts. Sending `SIGCONT` resumes it. Run this loop in a second terminal while Maestro runs:

```bash
while true; do for p in $(pgrep -f "maestro-driver-iosUITests-Runner$"); do
  case "$(ps -o stat= -p $p)" in T*) kill -CONT $p;; esac; done; sleep 1; done
```

If a run still fails, stop leftover xcodebuild processes (`pkill -f "xcodebuild test-without-building"`) and start the flow again. The root cause is not investigated. A high host load (17 to 30 after a reboot, from Spotlight) may contribute.

## 4. Configuration notes

From `mobile/app.config.ts`:

- **Bundle id** `com.bola8.staff`, same as Android.
- **buildNumber** = `String(APP_BUILD)` (CFBundleVersion). Mirrors Android `versionCode`.
- **App Transport Security**: `NSAllowsArbitraryLoads: true` and `NSAllowsLocalNetworking: true`. The app is an internal staff app distributed outside the App Store (TestFlight or Ad Hoc). It talks plain HTTP to the venue's LAN or Tailscale IP, which has no stable hostname. This matches Android's cleartext setting. The plan is to terminate TLS at nginx later.
- **NSLocalNetworkUsageDescription** (Spanish): "La app se conecta al servidor del bar en la red local."
- `ios/` is generated by `expo prebuild` and git-ignored. Never edit it by hand; change `app.config.ts` and re-run the build script with `--clean`.

## 5. Known issues

- **CoreSimulator can wedge.** If simulators stop responding or `simctl` hangs, reboot the Mac, then re-run `build-ios.sh`.
- **Auto-discovery only probes port 8080.** The local backend on 8090 is not found automatically. Enter `localhost:8090` manually on the setup screen.
- **Another POS on this LAN.** Discovery finds a different POS at **192.168.1.22:8080**. Never point the app or tests at it. Test credentials sent there would reach a live system.
- **Cold-cache Jest timeouts.** A few 5 s timeouts on a cold cache. A warm retry passes.
- **Low disk.** A build needs about 13 GB free.
- **Physical device not attempted.** The build has only been run on the simulator. A device build, the local-network prompt, and the LAN address have not been tested.
- **No EAS and no distribution yet.** No TestFlight or Ad Hoc build has been made.
- **Simulator keyboard sheet.** After a simulator reboot, the first keyboard use may show "Type English and Spanish" with a Continue button. Tap Continue once manually; the flows do not handle it.
